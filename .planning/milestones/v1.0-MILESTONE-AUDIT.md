## Cross-Phase Integration Issues

### Bug: Topic creation sends empty instruction (TOPIC-01)

`AddScope.tsx` has `instruction` field with `required={false}` and no `min` validation rule. When submitted blank, `createTopic()` sends `instruction: ""` to `POST /vdr-agent/topics`. The Pydantic `TopicCreate` model enforces `min_length=1`, returning HTTP 422. The UI shows a generic error without explaining the cause.

### Missing UI: No delete topic button (TOPIC-04)

The backend `DELETE /vdr-agent/topics/{id}` route is fully implemented (soft-delete via `is_active=false`), but no frontend component renders a delete button or calls this endpoint. TOPIC-04 is satisfied at the API level but unreachable from the UI.

### Orphaned function: getDocumentFitment never called (API-02, FE-02)

`vdrAgent.ts` exports `getDocumentFitment()` which calls `GET /vdr-agent/documents/{id}/fitment`. No component imports or calls this function. Per-topic fitment detail (reasoning text, per-topic status) is never rendered. `ScopeDetails.tsx` only shows aggregate `fitment_done_count / fitment_total_count` from the document list endpoint.

### Unused route: GET /documents/{id}/summary (API-01)

The dedicated per-document summary endpoint exists but is never called from the frontend. Summary text is accessible only via `DocumentListDAO.list_by_project()` in the document list response. API-01 is functionally satisfied through the list endpoint but the dedicated route is dead.

### Config placeholder: VDR_AGENT_BASE_URL (FE-01, FE-02, FE-03)

`config.ts` has `VDR_AGENT_BASE_URL: "https://TBD/"` in `DEV_CONFIG` and `PRE_PROD_CONFIG`. Only `LOCAL_CONFIG` has the correct `http://localhost:8004/vdr-agent`. Non-localhost deployments will fail.
