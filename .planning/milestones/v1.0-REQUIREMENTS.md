# Requirements: VDR Agent Service

**Defined:** 2026-03-05
**Core Value:** Every ingested document automatically gets an AI summary and a fitment evaluation per ESG topic — with no manual trigger required.

## v1 Requirements

### Topic Management

- [x] **TOPIC-01**: User can create a topic for a project with a name and instruction text
- [x] **TOPIC-02**: User can list all topics for a project
- [x] **TOPIC-03**: User can update a topic's name and instruction text
- [x] **TOPIC-04**: User can delete a topic from a project

### Document Processing

- [x] **PROC-01**: System polls for documents with completed embeddings and no AI summary using `FOR UPDATE SKIP LOCKED` (atomic claim, no duplicates)
- [x] **PROC-02**: System generates an AI summary per document (parallel section summaries → combined final summary)
- [x] **PROC-03**: System generates a fitment evaluation per active topic per document (uses AI summary + relevant sections + topic instruction)
- [x] **PROC-04**: System tracks processing status per document: `pending` → `processing` → `done` / `failed`

### Results API

- [x] **API-01**: User can retrieve the AI summary for a document
- [x] **API-02**: User can retrieve all fitment results for a document (one result per topic)
- [x] **API-03**: User can list documents for a project with their summary and fitment processing status

### Frontend Integration

- [x] **FE-01**: vdr-frontend loads topic names from vdr-agent API (replaces hardcoded ESG scope list)
- [x] **FE-02**: vdr-frontend shows fitment result per topic in the scope/document grid
- [x] **FE-03**: vdr-frontend shows processing status indicator (pending / processing / done) per document

## v2 Requirements

### Topic Management

- **TOPIC-05**: User can enable/disable a topic without deleting it
- **TOPIC-06**: When a topic instruction is updated, fitment is regenerated for all documents of that project

### Document Processing

- **PROC-05**: When a new topic is added, fitment is generated for all already-processed documents in the project (backfill)
- **PROC-06**: Failed documents are retried automatically on next polling cycle

### Results API

- **API-04**: User can retrieve all documents relevant/not-relevant for a specific topic

### Frontend Integration

- **FE-04**: vdr-frontend shows AI summary in document detail view
- **FE-05**: vdr-frontend allows filtering documents by topic relevance

## Out of Scope

| Feature | Reason |
|---------|--------|
| Temporal workflows | DB polling with asyncio is sufficient; Temporal adds infra overhead not justified at this stage |
| Retry logic | Skipped for now — failures are left as `failed` status, to be revisited in v2 |
| Authentication in vdr-agent | Internal service; defer to user-service SSO for now |
| Fitment re-run on instruction change | Deferred to v2 — TOPIC-06 |
| New topic backfill | Deferred to v2 — PROC-05 |
| Document upload | Documents come from SharePoint via ingestion-service only |
| Show AI summary in frontend | Deferred to v2 — FE-04 |
