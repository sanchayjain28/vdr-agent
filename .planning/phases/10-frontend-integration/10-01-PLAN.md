**Service functions:**

`getTopics(projectId: string): Promise<ITopic[] | undefined>` — calls `GET topics` with `{ params: { project_id: projectId } }` via `get(vdrAgentApi, ...)`. On error: `console.error` + `toast.error("Failed to load topics.")` + return `undefined`.

`getVdrDocuments(projectId: string): Promise<IDocumentListItem[] | undefined>` — calls `GET documents` with `{ params: { project_id: projectId } }`. On error: `console.error` only (no toast — this is polled; repeated toasts on network blip would be disruptive). Special handling: if the error response status is 404 (empty project), return `[]` (empty array) not `undefined` — prevents toast from firing for projects with no documents.

`getDocumentFitment(documentId: string): Promise<IFitmentItem[] | undefined>` — calls `GET documents/${documentId}/fitment`. On error: `console.error` + return `undefined`.

Import pattern:
```typescript
import { toast } from "react-toastify";
import { get, vdrAgentApi } from "./apiClients";
```

The 404 check for `getVdrDocuments`: `(error as any)?.status === 404 || (error as any)?.response?.status === 404` — return `[]` in that branch. Note: apiClients.ts response interceptor rejects with `err?.response?.data || err`, so the error shape may be the response data object rather than a standard AxiosError — check both paths.
